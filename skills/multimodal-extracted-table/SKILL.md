# 图片/PDF/Office 抽表数据

## 适用判断
- series 来自图片、PDF、扫描件、docx/pptx/xlsx 内嵌表格截图或文档表格化。
- 数据列名可能来自 OCR/视觉模型，存在合并表头、单位、脚注、多个表格并存的情况。

## 规划阶段
- 先看 `df` 预览和列名，确认哪张表是用户要的主表；多表时不要把不同表硬拼成一个系列。
- 列名保持原样（包括年份、单位、百分号），不要为了“更好看”改写列名。
- 如果列名/单位/时间范围存在影响结果的歧义，写入 ambiguities / assumptions；
  不要静默猜测后当作确定值。
- 图表标题可以指出数据来源（如“报表截图：2024 年销售额”），但不要编造原始文件里没有的信息。

## 生成阶段
- 只使用真实存在的列；不要补造缺失行、缺失列或“看起来应该有的”合计。
- 单位优先从列名/表头提取，写进轴名或副标题；不要擅自把“万元”改成“元”。
- 缺失值按原始表处理：能画就画，不能画就在 assumptions 说明；不要用 0 填充后当作真实值。
- 如果一图多表被拆成多个 series，优先选与用户需求最匹配的一张；其余可在说明里提示。
- 视觉上按普通表格处理即可；不要把“来自图片”当成改变图表类型的理由。

## 不要做
- 不要因为 OCR 结果不整齐就重新命名所有列。
- 不要把扫描件的页眉、页码、脚注当成数据行。
- 不要在没有依据时补全合并单元格里的数值。
