# Rust + Win32 前端开发技术资料

> 本文档为 DataVisualServer 前端（`datavisual-frontend`）的技术调研资料。
> 当前采用 Rust + 纯 Win32 API 开发原生 Windows 桌面应用，
> 通过 HTTP/WebSocket 与 DataVisualServer 后端（Flask）交互。
>
> ⚠️ 更新于 2026-07-25：文档已与实际代码同步。原计划的 WinUI3 方案因
> Reactor 未发布而改为纯 Win32 API。未来 Reactor 发布后可迁移。

## 1. 概述

DataVisualServer 前端定位为原生 Windows 桌面客户端，核心职责：

- 通过 Win32 文件选择器上传 Excel/CSV 数据文件（支持拖拽）
- 触发后端 LLM 分析，通过 WebSocket 实时接收任务状态和执行日志
- 用系统浏览器打开后端生成的 HTML 图表（WebView2 嵌入待实现）
- 管理历史对话记录（SQLite 持久化），支持查看/删除/修改提示词重提

### 1.1 设计目标

| 指标 | 目标 | 当前状态 |
|------|------|---------|
| 包体积 | < 10 MB（release） | ✅ debug 8.5 MB |
| 启动时间 | < 1s | 待测量 |
| 最低系统 | Windows 10 1809 | ✅ Win32 无特殊要求 |
| UI 框架 | Win32 API | ✅ 当前方案 |
| 渲染方式 | WebView2 嵌入 | ⏳ 当前用外部浏览器 |
| 异步模型 | tokio + std::thread | ✅ |
| 通信方式 | HTTP + WebSocket | ✅ |

## 2. 技术方案选型对比

### 2.1 候选方案对比表

| 维度 | windows-rs (Reactor) | windows-rs (纯 Win32) | winio-ui-winui | Tauri |
|------|---------------------|----------------------|----------------|-------|
| 抽象层级 | 底层绑定 + XAML 投影 | 最底层 COM/Win32 绑定 | 中高层封装 | 高层框架 |
| WinUI 3 支持 | 实验性 XAML 互操作 | 需手动加载 WinRT | 内置封装 | 不支持（WebView2） |
| 学习曲线 | 陡（需懂 COM/WinRT） | 极陡 | 平缓 | 平缓（Web 技术） |
| 包体积 | 小（约 2 MB） | 极小（< 1 MB） | 小 | 中（3-5 MB，含 WebView2 loader） |
| 异步模型 | WinRT Async + Rust async | 手动消息循环 | tokio + 事件循环 | tokio + IPC |
| 生态成熟度 | 实验性（PR 阶段） | 稳定 | 早期 | 成熟 |
| 图表渲染 | XAML 控件 / WebView2 | 自绘 GDI/Direct2D | WinUI 控件 | WebView2（最佳） |
| 维护方 | microsoft/windows-rs | microsoft/windows-rs | winio 社区 | Tauri 团队 |
| 热重载 | 否 | 否 | 否 | 是（前端 Web） |
| 原生控件外观 | 是（Fluent） | 否（经典 Win32） | 是（Fluent） | 是（WebView2 模拟） |

### 2.2 选型结论

本项目选用 **windows-rs（含 Reactor 实验性 XAML 支持）** 作为主方案：

1. **官方维护**：microsoft/windows-rs 长期可靠，跟进 Windows SDK 更新
2. **全 API 访问**：可直接访问 WinUI 3 / XAML / Win32 / WinRT 全套 API
3. **WebView2 互操作**：可嵌入 WebView2 渲染 pyecharts 输出的 HTML，零成本复用后端产物
4. **体积可控**：release profile 开启 `opt-level="z"` + LTO + strip，符合单文件分发目标
5. **edition 2024**：享受最新 Rust 语言特性

**风险与缓解**：

- Reactor XAML 投影仍处于实验阶段（PR #4479），API 可能变动 → 锁定特定 commit，固定 `Cargo.lock`
- 文档稀缺 → 参考仓库 examples 与微软官方 WinRT 文档对照

## 6. 核心代码示例

### 6.1 Hello World（窗口创建）

```rust
use windows::{
    Win32::{
        Foundation::*,
        UI::WindowsAndMessaging::*,
        System::LibraryLoader::GetModuleHandleW,
    },
    core::*,
};

/// 创建并显示主窗口，进入消息循环
fn main() -> Result<()> {
    unsafe {
        let h_instance = GetModuleHandleW(None)?;
        let class_name = w!("DataVisualWindow");

        let wc = WNDCLASSW {
            lpfnWndProc: Some(defwndproc),
            lpszClassName: class_name,
            hInstance: h_instance.into(),
            style: CS_HREDRAW | CS_VREDRAW,
            ..Default::default()
        };
        RegisterClassW(&wc);

        let hwnd = CreateWindowExW(
            WINDOW_EX_STYLE::default(),
            class_name,
            w!("DataVisualServer 前端"),
            WS_OVERLAPPEDWINDOW,
            CW_USEDEFAULT,
            CW_USEDEFAULT,
            900,
            600,
            None,
            None,
            h_instance,
            None,
        )?;

        ShowWindow(hwnd, SW_SHOW);

        let mut msg = MSG::default();
        while GetMessage(&mut msg, None, 0, 0).into() {
            TranslateMessage(&msg);
            DispatchMessage(&msg);
        }
    }
    Ok(())
}
```

> 生产环境使用 Reactor XAML 投影创建 `Application` + `Window`，以上为 Win32 兜底最小示例。

### 6.2 API 交互（reqwest + tokio）

```rust
use serde::{Deserialize, Serialize};

#[derive(Debug, Serialize)]
pub struct UploadRequest {
    pub filename: String,
}

#[derive(Debug, Deserialize)]
pub struct PlanResponse {
    pub plans: Vec<ChartPlan>,
}

#[derive(Debug, Deserialize)]
pub struct ChartPlan {
    pub id: usize,
    pub title: String,
    pub chart_type: String,
    pub status: String,
}

/// 调用后端生成图表计划
///
/// 参数:
/// - base_url: 后端地址，如 `http://127.0.0.1:5000`
/// - file_path: 待上传的数据文件绝对路径
///
/// 返回: 解析后的计划列表
pub async fn generate_plans(
    base_url: &str,
    file_path: &str,
) -> anyhow::Result<PlanResponse> {
    let client = reqwest::Client::new();
    let resp = client
        .post(format!("{}/api/generate", base_url))
        .multipart(
            reqwest::multipart::Form::new().file("file", file_path)?,
        )
        .send()
        .await?
        .json::<PlanResponse>()
        .await?;
    Ok(resp)
}
```

### 6.3 文件选择器（FileOpenPicker）

```rust
use windows::Storage::Pickers::FileOpenPicker;
use windows::Foundation::*;
use windows::core::*;

/// 弹出文件选择器，返回所选文件路径
///
/// 支持 .csv / .xlsx / .xls 格式。
/// 返回: 选中文件的绝对路径，若用户取消则返回错误。
pub async fn pick_data_file() -> anyhow::Result<String> {
    let picker = FileOpenPicker::new()?;
    picker.FileTypeFilter()?.Append(w!(".csv"))?;
    picker.FileTypeFilter()?.Append(w!(".xlsx"))?;
    picker.FileTypeFilter()?.Append(w!(".xls"))?;

    let file: IStorageFile = picker
        .PickSingleFileAsync()?
        .await?
        .ok_or_else(|| anyhow::anyhow!("未选择文件"))?
        .into();

    let path = file.Path()?;
    Ok(path.to_string())
}
```

## 7. 与 DataVisualServer 后端对接

### 7.1 API 端点映射

| 前端功能 | HTTP 方法 | 后端端点 | 请求体/参数 | 说明 |
|---------|----------|---------|-----------|------|
| 上传数据文件 | POST | `/api/upload` | multipart (file) | 支持 csv/xlsx |
| 生成图表计划 | POST | `/api/generate_plan` | JSON { filename } | 触发 LLM 分析 |
| 获取计划列表 | GET | `/api/plans` | - | 返回 all_plans.json |
| 生成单个图表 | POST | `/api/chart/<id>` | JSON { id } | 返回 HTML 路径 |
| 获取图表 HTML | GET | `/charts/<file>/chart_*.html` | 路径参数 | 静态文件服务 |
| 调试图图 | POST | `/api/debug_chart` | JSON { id, error } | 失败重试（最多 3 次） |
| 健康检查 | GET | `/api/health` | - | 返回服务状态 |

> 实际端点以 `app.py` 注册为准，此处为对接约定。

```
│  用户操作     │ ───────────────────────────▶ │  前端 UI    │
└──────────────┘                                │ (WinUI 3)   │
                                                └──────┬──────┘
                   2. multipart 上传              │
                       /api/upload                ▼
                ┌────────────────────────────────────┐

                                 │ 3. HTTP

                ┌────────────────────────────────────┐
                │   DataVisualServer (Flask :5000)    │
                │   ┌──────────┐   ┌──────────────┐   │
                │   │ app.py   │──▶│ service_main │   │
                │   └──────────┘   └──────┬───────┘   │
                │                         │ 4. LLM    │
                │                         ▼           │
                │                  ┌─────────────┐    │
                │                  │ chart_gen   │    │
                │                  │ + RAG + MCP │    │
                │                  └──────┬──────┘    │
                │                         │ 5. .render│
                │                         ▼           │
                │                  charts/**/*.html   │
                └─────────────────────────┬──────────┘
                                          │ 6. 返回路径/JSON
                                          ▼
                ┌────────────────────────────────────┐
                │   前端 WebView2 加载 HTML 渲染      │
                │   (pyecharts 输出原样展示)          │
                └────────────────────────────────────┘
```

**关键交互说明**：

1. 用户在前端选择本地数据文件
2. 前端通过 reqwest multipart 上传至后端 `/api/upload`
3. 后端 `app.py` 路由至 `service_main` 处理管线
4. `chart_generator` 调用 LLM agent 分析数据并生成图表计划
5. RAG 检索图表知识库，MCP 工具执行 pyecharts `.render()` 输出 HTML
6. 前端获取 HTML 路径，WebView2 加载并渲染图表

## 10. 注意事项

1. **Reactor 实验性**：XAML 互操作（PR #4479）尚未合入稳定分支，API 可能频繁变动。建议锁定到具体 commit，并在 CI 中固定 `Cargo.lock`，避免依赖漂移导致编译失败。升级前务必查阅 PR 评论与 breaking changes。

2. **XAML 互操作**：WinUI 3 XAML 树必须在 STA（单线程单元）上操作。从 tokio 异步任务回到 UI 线程需使用 `DispatcherQueue::TryEnqueue`，禁止在工作线程直接更新控件，否则会引发 COM 异常。

3. **WebView2 嵌入**：pyecharts 输出的 HTML 依赖 ECharts JS（内联或外链）。
   - 若内联 JS，可直接 `NavigateToString`
   - 若外链 CDN，需确保运行环境联网，或预先打包 `echarts.min.js` 到本地资源
   - 推荐用 `NavigateToLocalStreamUri` 加载本地 HTML 文件，配合 `IUriToStreamResolver` 映射资源

4. **异步模型**：
   - UI 线程跑消息循环，禁止 `block_on` 阻塞
   - 后台 IO 用 `tokio::spawn`，结果通过 channel（如 `tokio::sync::oneshot`）回传 UI
   - WinRT `IAsyncAction`/`IAsyncOperation` 用 `.await` 桥接，注意取消语义

5. **Rust edition 2024**：
   - 需 Rust 1.85+ 工具链
   - `unsafe` 操作更严格（`unsafe_op_in_unsafe_fn` 默认 warn/deny），unsafe 函数内的 unsafe 操作需再次包裹 `unsafe {}`
   - 新增 `gen` 关键字保留（为生成器准备），命名冲突需注意
   - `Cargo.lock` 行为与依赖解析与 2021 一致

6. **MSVC 链接器**：`.cargo/config.toml` 显式指定 `linker = "link.exe"`，确保走 MSVC 链接器而非 lld。若报「找不到 link.exe」，检查 VS Build Tools 是否安装「C++ 生成工具」组件，并确认 `cl.exe` / `link.exe` 在 PATH 中（或通过「Developer PowerShell for VS 2022」启动终端）。

7. **Windows App SDK 运行时依赖**：
   - MSIX 安装会自动拉取运行时（声明 `<PackageDependency>`）
   - 若免安装分发（独立 exe），需打包 WindowsAppRuntime 文件并调用 `MddBootstrapInitialize` 初始化
   - 首次启动需检测运行时是否已安装，缺失时引导用户安装

8. **字符编码**：Windows API 的宽字符为 UTF-16，Rust 字符串为 UTF-8。跨边界传递时用 `windows::core::HSTRING` 与 `PCWSTR`，避免手动编码转换出错。中文路径务必通过 `HSTRING::from` 转换。
