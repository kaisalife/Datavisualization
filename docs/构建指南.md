# 前端构建指南

## 环境要求

### 1. Rust 工具链

```powershell
# 安装 Rust（https://rustup.rs）
rustup-init.exe

# 验证版本（需要 1.85+，因为使用 edition 2024）
rustc --version
```

工具链二选一即可：
- **MSVC**（推荐，与 `.cargo/config.toml` 里的 `target = "x86_64-pc-windows-msvc"` 一致）：
  `rustup default stable-x86_64-pc-windows-msvc`
- **GNU**：`rustup default stable-x86_64-pc-windows-gnu`，构建时显式指定
  `cargo build --target x86_64-pc-windows-gnu`（产物路径会多一层 target 目录）

### 2. 链接器

| 工具链 | 需要安装 |
|--------|----------|
| MSVC | VS Build Tools 2022，勾选 **MSVC v143 - VS 2022 C++ x64/x86 生成工具** + 一个 Windows SDK。下载：https://visualstudio.microsoft.com/visual-cpp-build-tools/ |
| GNU | MinGW-w64（提供 `gcc`/`ld`），例如 https://www.mingw-w64.org/ |

### 3. Windows App Runtime（**必需**）

前端是 **WinUI3** 应用（`front-winui/Cargo.toml` 中 `winio` 的 `winui` feature），
通过 `winio` 的 WinUI 后端运行。**非 MSIX 打包**的 exe 无法自行完成 WinRT 类注册，
必须在 exe 同目录提供运行库，否则启动即失败：

| 缺失 | 现象 |
|------|------|
| 完全没有运行库 | 启动即退出，报 `0x8007007E`（找不到指定的模块） |
| 放了 `Microsoft.ui.xaml.dll` | 创建 XAML 对象时崩溃 `0x80040154`（没有注册类） |

`front-winui/scripts/setup-windows-app-runtime.ps1` 负责从已安装的
Windows App Runtime 框架包中拷贝所需的**最小文件集合**，每次 `cargo build` 之后执行一次：

```powershell
powershell -ExecutionPolicy Bypass -File front-winui\scripts\setup-windows-app-runtime.ps1 -Clean
```

> ⚠️ 脚本刻意**不拷贝** `Microsoft.ui.xaml.dll`：`winio` 只要发现该 DLL 可加载，
> 就会跳过"把框架包挂进进程"的注入流程，反而导致类未注册。
> 运行库需要由"包"提供，而不是简单地把所有 DLL 堆在 exe 旁边。

Windows App Runtime 本身随 Windows App SDK 运行时安装：
https://aka.ms/windowsappsdk/1.8/latest/windowsappruntimeinstall-x64.exe
（实测 Win10 22H2 可用；机器上通常已随其他应用装好框架包，脚本会自动找。）

### 4. 不需要的东西

| 不需要 | 原因 |
|--------|------|
| .NET SDK | Rust 项目不需要 |
| MSIX 打包工具 | 可选，仅在发布时需要 |
| Node.js / npm | 前端 JS 由 Rust 内嵌，无构建步骤 |

## 构建

### Debug 构建（开发用）

```powershell
cd front-winui
cargo build                       # MSVC 工具链（用 .cargo/config.toml 里的默认 target）
cargo build --target x86_64-pc-windows-gnu   # GNU 工具链
```

产物位置：
- MSVC：`front-winui/target/x86_64-pc-windows-msvc/debug/datavisual-winui.exe`
- GNU：`front-winui/target/x86_64-pc-windows-gnu/debug/datavisual-winui.exe`

首次编译约 5 分钟（需要下载 ~400 个依赖），增量约 5 秒。

### Release 构建（发布用）

```powershell
cd front-winui
cargo build --release
```

产物为 `front-winui/target/<target>/release/datavisual-winui.exe`
（已配置 `opt-level="z"` + `lto=true` + `strip=true`）。

### 类型检查（快速验证，不生成 .exe）

```powershell
cd front-winui
cargo check
```

## 运行

### 前置条件 1：后端必须先启动

```powershell
# 在项目根目录
.venv\Scripts\python.exe app.py
# 后端默认监听 http://localhost:5000
```

### 前置条件 2：准备 WinUI3 运行库

见上文「环境要求 → 3. Windows App Runtime」。`cargo clean` 之后必须重新执行。

### 启动前端

```powershell
$dest = "front-winui\target\x86_64-pc-windows-gnu\debug"   # 按实际工具链调整

# 1) 拷贝运行库（每次构建后执行一次）
powershell -ExecutionPolicy Bypass -File front-winui\scripts\setup-windows-app-runtime.ps1 -Clean

# 2) 启动（方式 1：直接运行 exe）
$env:BACKEND_URL = "http://localhost:5000"
& "$dest\datavisual-winui.exe"

# 方式 2：通过 cargo run（同样需要先跑上面的脚本）
cd front-winui
cargo run
```

启动成功的标志：窗口标题为 `DataVisual - 多源数据可视化平台`，
控制台出现 `[Bridge] HTTP 服务器启动在 127.0.0.1:<随机端口>`。

### 环境变量配置

前端通过环境变量配置后端地址和高级参数：

```powershell
# 必需：后端地址（默认 http://localhost:5000）
$env:BACKEND_URL = "http://localhost:5000"

# 必需：API Key（如果后端启用了认证）
$env:API_KEY = "your-api-key"

# 可选：模型配置
$env:MODEL_URL = "https://api.openai.com/v1"
$env:MODEL_TYPE = "openai"
$env:MODEL_API_KEY = "your-model-api-key"

# 可选：提示词
$env:MCP_PROMPT = "..."
$env:SKILL_PROMPT = "..."
```

## 常见问题

### Q: 启动后立刻退出，报 `Error(找不到指定的模块。(0x8007007E))`

A: exe 同目录缺少 `Microsoft.WindowsAppRuntime.dll`。
执行 `front-winui\scripts\setup-windows-app-runtime.ps1`，或确认机器上已安装
Windows App Runtime 框架包（`Get-AppxPackage Microsoft.WindowsAppRuntime.1.8`）。

### Q: 启动即崩溃，事件日志里是 `Microsoft.ui.xaml.dll` + `0xc000027b`

A: 崩溃的根因是 `0x80040154`（没有注册类）。通常是 exe 目录里被放入了
`Microsoft.ui.xaml.dll`，使 `winio` 误判运行库已就绪、跳过了把框架包挂进进程的注入步骤。
删掉该 DLL，改用 `setup-windows-app-runtime.ps1` 拷贝的最小集合。

### Q: `error: linker 'link.exe' not found`

A: 使用 MSVC 工具链时需安装 VS Build Tools 2022（"MSVC v143 C++ x64/x86 生成工具"）；
或者改用 GNU 工具链：`cargo build --target x86_64-pc-windows-gnu`。

### Q: 编译报错 `edition 2024 is unstable`

A: 更新 Rust：`rustup update stable`，确认 `rustc --version` >= 1.85。

### Q: 前端启动后连接后端失败

A: 确认后端已启动（`python app.py`），且 `BACKEND_URL` 环境变量正确。

### Q: WebSocket 连接失败

A: 确认后端安装了 `flask-sock`（`pip install flask-sock`）。前端会自动回退到轮询模式。
