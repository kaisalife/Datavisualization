# 调研结论：有没有现成的多模态数据清洗工具集？

## 调研范围与方法

- 本地仓库：`skills/`、`agent_tools/`、`configs/default_config.json`、`service/data_ingestion/`、`tests/`；
- 本地现状：`skills/` 只有 4 个图表场景技能（高频时序、K 线、多序列、多模态抽表），没有数据清洗技能；
  `agent_tools/` 只有 `run_code` MCP，没有清洗/质量检查工具；
- 外部检索：MCP 目录 / GitHub / 官方文档 / Skills 合集；
- 检索关键词：`data cleaning MCP`、`multimodal data cleaning`、`OCR table extraction MCP`、
  `Claude skill data cleaning`、`数据清洗 MCP`、`多模态 数据清洗` 等；
- 重点判断标准：
  1. 是否同时覆盖**图片 / PDF / Office 内嵌表格**与**表格清洗**；
  2. 是否有**确定性规则**与**质量报告**，而不是只做 OCR/文本提取；
  3. 是否适合本项目：Windows、本地优先、Python、中文报表、无需 GPU、可与现有 pipeline 对接。

## 结论

**没有找到一个可以直接替换本项目数据接入层的“多模态数据清洗”skill/MCP 工具集。**

现成项目大多只覆盖其中一段：

- 文档解析工具负责“把图片/PDF 变成文本或表格”，但不判断表头是否正确、数值是否可解析、是否有缺失/重复/异常；
- 表格清洗工具负责“对 DataFrame 做 pandas 操作”，但默认输入已经是干净的表，不理解扫描件、合并表头、跨页续表；
- Agent Skills 负责“告诉模型怎么做”，但多数是通用 pandas/numpy 步骤，缺少面向中文报表的确定性规则和审计。

因此建议的组合是：**现有 reader 负责多模态接入，项目内新增确定性清洗层，Docling/OCRFlux 只在抽取失败时作为可选适配器，最后用 skill + MCP 暴露给 agent。**

## 为什么不自建“万能清洗大模型”

- 让 LLM 直接改数据，无法保证同一输入得到同一输出，也无法解释每一行为什么被改；
- 缺失值填 0、按均值填充、删除“异常值”在业务上可能是错误操作，必须由用户或明确规则决定；
- 图表任务需要的是**可复现的表格与 series**，不是一段看起来合理的叙述；
- 本项目已经有确定性 reader 和 profiler，正确做法是补确定性清洗层，而不是推倒重来。

## 推荐路线

### P0：项目内确定性清洗层（默认）

- 新增 `service/data_ingestion/cleaning/`：
  - `rules.py`：规则定义与严重级别；
  - `profile.py`：质量检查（缺失、重复、异常、类型、单位、时间连续性）；
  - `plan.py`：清洗计划（dry-run / commit）；
  - `report.py`：清洗报告 JSON；
  - `apply.py`：把计划应用到 DataFrame。
- 复用现有 `_normalize_columns`、`coerce_numeric_columns`、Excel 表头处理、series 拆分。
- 默认只自动执行低风险、可逆规则；其余生成建议。
- 输出 `cleaning_report.json`，与 `DataProfile`、series 一起落盘。

### P1：Skill + MCP 暴露

- `skills/multimodal-data-cleaning/SKILL.md`：告诉 agent 先 profile、再检查、再 dry-run、最后确认。
- `agent_tools/tool_data_cleaning.py`：FastMCP server，暴露 `profile_table`、`detect_issues`、`apply_cleaning_plan`、
  `validate_table`、`export_table` 等工具。
- `configs/default_config.json` 增加 `mcp_config.data_cleaning`，按需启用，不影响现有 `run_code`。

### P2：外部抽取器适配（按需）

- 当 `MultimodalReader` / `OfficeImageReader` 抽表失败或结构明显退化时，尝试 Docling/OCRFlux；
- 外部工具只负责“抽取”，输出仍进入同一套 `RawTable → 清洗 → profiler → series` 流程；
- 用 feature flag 控制，默认关闭，避免引入大依赖和不可控延迟。

## 关键取舍

| 问题 | 选择 | 理由 |
|---|---|---|
| 是否自动填充缺失值 | 否，默认只报告 | 填充策略依赖业务语义，错误填充比缺失更危险 |
| 是否自动删除重复行 | 否，默认只报告 | “重复”可能是多批次/多门店的真实记录 |
| 是否自动剔除异常值 | 否，默认只报告 | 异常值可能是真实尖峰，直接删会改变结论 |
| 是否自动换算单位 | 否，除非列名/规则明确 | `万元` 与 `元` 混用必须显式确认 |
| 是否让 LLM 生成清洗计划 | 可以建议，但执行前必须转成结构化规则并 dry-run | 保证可审计、可复现 |
| 是否把清洗结果覆盖原表 | 否 | 保留原始表，支持回溯和对比 |
