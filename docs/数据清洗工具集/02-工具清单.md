# 工具清单

本清单分两层：

- **已有能力**：项目里已经实现、已经过测试的清洗/接入能力，优先复用；
- **候选工具**：外部可接入的能力，按“是否值得引入、引入到哪一层”分类。

> 原则：能用确定性代码解决的，不引入 LLM；能用现有模块解决的，不新增依赖；外部工具只补缺口。

## 三、依赖策略

### P0：不新增强制依赖

- 使用已有 `pandas`、`openpyxl`、`xlrd`、`pyarrow`、`unstructured`、`pypdfium2`、`pillow`；
- 质量检查用 pandas/numpy 手写，规则少而明确，避免为了一个缺失率引入新框架；
- 清洗报告用标准 JSON + HTML（复用现有报告/预览的静态资源思路）。

### P1：可选依赖

如果后续需要更复杂的 schema 校验，再考虑：

```toml
[project.optional-dependencies]
cleaning = [
    "pandera>=0.20",   # DataFrame schema / 约束
]
```

> 不要直接改 `dependencies`。新增依赖前先确认真实需求、许可证、Windows 兼容性和安装体积。

### P2：外部抽取器

- Docling / OCRFlux 作为**可选 extra** 或独立进程/容器，不进入默认安装；
- 通过环境变量或配置开关启用，例如 `CLEANING_DOCLING=1`；
- 失败时回退到现有 `MultimodalReader`，不能因为外部工具不可用导致整条链路失败。

## 四、明确不做的事

- 不用 LLM 直接“清洗”整张表并覆盖原数据；
- 不自动把缺失值填 0 / 均值 / 前向填充；
- 不自动删除重复行或异常值；
- 不自动把 `万元` 转成 `元`、把百分比转成小数，除非用户明确要求；
- 不把多个来源不同的表按列名相似度自动合并；
- 不为了“看起来干净”而重命名所有列，列名保真是多模态抽表的基本要求。
