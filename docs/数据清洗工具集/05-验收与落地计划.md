# 验收与落地计划

原则：**每一步都必须能在真实图表路径里证明价值**，不追求规则数量。
默认路径（identity view）零改动地保留；派生 view 只在用户/agent 真实需要时被触发。

## P0：核心库骨架（不改 plan schema，不影响现有链路）

交付物：

- `service/data_view/spec.py`：`ViewSpec` dataclass、hash、校验（只读 SQL / 已注册插件）；
- `service/data_view/engine.py`：SQLite（内存）执行、稳定排序、行数阈值、结构化错误；
- `service/data_view/cache.py`：`view_id -> parquet + manifest.json` 落盘与命中；
- `service/data_view/registry.py`：插件目录扫描（首版可零插件，注册表为空也成立）；
- 回归：`tests/test_data_view_spec.py`（hash 稳定性、非法 spec 拒绝）、
  `tests/test_data_view_engine.py`（聚合/透视/Top-N SQL、多语句拒绝、行数上限）、
  `tests/test_data_view_cache.py`（同 spec 命中、数据变更 miss、失败不缓存）。

完成标准：

- `ViewSpec("select ... group by ...")` 能从 RawTable 生成物化 view，重复执行命中缓存；
- 写操作 / 多语句 / 未声明排序输出被拒绝且错误码稳定；
- 现有全部核心回归（`tests/test_refactor_smoke.py` 等）零退化——P0 不接主链路。

## P1：接入主链路（series/plan 只加不改）

交付物：

- `splitter` 产出的 series manifest 增记来源（identity / view 派生），plan schema 不变；
- `agent_tools/tool_data_view.py`：`describe_dataset` + `run_view`（fastmcp，stdio）；
- `api/data_profile_api.py` 预览响应带已有 view 列表；
- 技能索引里加一条 `data-view-usage` 技能（何时造派生 view、典型 SQL 模板）；
- 真机验证一条路径：上传长表 → 规划 agent 发现缺"按月合计"视角 → `run_view` → 出图。

完成标准：

- 真机：说"按月合计画柱状图"而数据是明细行时，列表里多出一条 view 系列，
  plan 引用它而不是生成器里现写 groupby；
- 不提要求时任务耗时与现状持平（0 次额外 LLM 调用、0 次额外 SQL 执行）；
- `view_id` 稳定：同一任务重跑，`describe_dataset` 返回同 id，不重算。

## P2：扩展与增强（按需，不预做）

- 插件首批：K 线重采样、高频时序聚合（这两个场景 SQL 不好写、已有技能背书）；
- 大表引擎可选：DuckDB 后端（新增依赖需走清华镜像装包 + `uv lock` 流程，非默认）
- 预览前端：展示 views 列表与 spec 摘要（读 API 即可，无交互协议新增）；
- `chart_data_check` 反馈：若失败原因指向"数据视角不对"，错误信息提示规划 agent
  可再造 view——只加提示语，不加新阶段。

## 测试矩阵

| 测试 | 免 LLM？ | 覆盖 |
|---|---|---|
| `test_data_view_spec.py` | 是 | hash 确定、非法 spec（写语句/多语句/无 order）拒绝 |
| `test_data_view_engine.py` | 是 | 聚合/透视/Top-N/join、行数上限、错误码 |
| `test_data_view_cache.py` | 是 | 同 spec 命中、数据 hash 变更 miss、失败否决缓存 |
| `test_data_view_plugin.py` | 是 | 插件注册、params 透传、禁 IO/随机的静态声明 |
| `test_data_view_mcp.py` | 是 | 两个工具的参数校验与句柄解析、路径穿越拒绝 |
| `tests/test_file/test_data_view_e2e.py` | 否（真机） | 长表 → run_view → plan → 图表 HTML 数值一致 |

真机验收口径（与既有图表验收一致）：

- 图表 HTML 里的数值与 view parquet 一致（不是与原始表一致——用户要的就是变换后的视角）；
- 同一 prompt + 同一文件重跑，plan 引用同一 `view_id`；
- 失败路径：坏 SQL 返回结构化错误，任务给出可读原因，不静默出空图。

## 性能预算（防"流程变长"回潮）

| 步骤 | 预算 |
|---|---|
| `spec` 校验 + hash | < 1 ms |
| SQLite 内存执行（≤10 万行） | < 300 ms |
| 缓存命中 | < 10 ms（parquet 读取） |
| MCP 一次往返 | 叠加现有单进程 stdio 开销，无新增网络跳 |

派生 view 只允许出现在"数据必须加工才能画出用户要的图"的场景；
纯读取（identity）场景的耗时曲线与现状完全重合——这是自查标准。
