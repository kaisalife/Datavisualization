# 清洗流程与规则

## 1. 总体流水线

```text
原始输入（文件 / DB / API / 图片 / PDF / Office）
        │
        ▼
┌─────────────────────┐
│ 1. 注册与识别        │  MIME、扩展名、编码、大小、哈希、来源
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│ 2. 抽取为 RawTable   │  CSV/Excel/JSON/DB/API/视觉模型/OCR/文档解析
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│ 3. 结构清洗          │  标题行、合并表头、空白 sheet、列名、重复列
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│ 4. 值清洗            │  数值文本、空值占位符、类型、空白、编码
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│ 5. 质量检查          │  完整性、唯一性、有效性、一致性、时间连续性
└─────────────────────┘
        │
        ├── 无阻断问题 ──► 6. 语义画像 → series 拆分 → 图表
        │
        └── 有阻断问题 ──► 7. 清洗计划（dry-run）→ 用户/agent 确认 → commit
                                      │
                                      └── 重新执行 5/6
```

### 各阶段职责

| 阶段 | 输入 | 输出 | 是否允许自动修改 |
|---|---|---|---|
| 注册与识别 | 原始路径/字节 | 来源元数据 | 否（只读） |
| 抽取 | 原始输入 | `RawTable` | 是（reader 内部必要转换） |
| 结构清洗 | `RawTable.df` | 规范化列名/表头 | 是（低风险、可逆） |
| 值清洗 | `DataFrame` | 数值/空值/类型规范化 | 是（保守、整列回退） |
| 质量检查 | `DataFrame` + `DataProfile` | `CleaningIssue[]` | 否（只报告） |
| 清洗计划 | `CleaningIssue[]` + 用户意图 | `CleaningAction[]` | 只有显式确认后 |
| 语义画像 | 清洗后 `DataFrame` | `DataProfile` / `SeriesCatalog` | 是（不改变值） |

## 2. 规则目录

### 2.1 可自动执行（低风险、可逆、可解释）

| 规则码 | 触发条件 | 默认动作 | 说明 |
|---|---|---|---|
| `HEADER_WHITESPACE` | 列名含首尾空白/换行/制表符 | 去空白、压成单空格 | `" 城市 "` → `城市` |
| `HEADER_DUPLICATE` | 重复列名 | 加 `.1` / `.2` 后缀 | 不合并列，避免数据丢失 |
| `HEADER_EMPTY` | 空列名 | 命名为 `Unnamed` 或按位置补名 | 保留列，后续提示 |
| `TITLE_ROW` | 顶部跨列单值合并行 | 跳过标题行 | 最多 2 行 |
| `MERGED_HEADER` | 表头区域有纵向/横向合并 | 压成单行，`_` 连接 | 纵向重复值去重 |
| `BLANK_SHEET` | 只有标题、0 行数据、全空 | 跳过该 sheet | 防止主表变成空表 |
| `MERGED_TEXT_DOWN` | 数据区文本纵向合并 | 向下填充文本 | 数值合计不填 |
| `ENCODING` | CSV/TSV 编码不确定 | UTF-8 BOM > UTF-16 > UTF-8 > GB18030 | 失败时给出明确错误 |
| `DELIMITER` | 分隔符不确定 | 引号外计数嗅探 | `"说明,含逗号"` 不误判 |
| `NUMERIC_TEXT` | 整列都是可解析数值文本 | 转数值 | 任一失败整列保留 |
| `NULL_TOKEN` | 空值占位符且其余值为数字 | 转 NaN | `—` / `暂无` / `N/A` |
| `WHITESPACE_VALUE` | 文本值首尾空白 | 去空白 | 不改变中间内容 |
| `JSON_NESTED` | JSON 嵌套对象 | 展开为点号列 | 保留原字段名 |

> 这些规则必须**幂等**：同一张表重复执行，结果不变；执行前后行数不变（除非明确说明了跳过 sheet/行）。

### 2.2 只报告，需显式确认

| 规则码 | 检查内容 | 默认动作 | 可选动作（需确认） |
|---|---|---|---|
| `MISSING_VALUES` | 每列缺失数/比例 | 报告 | 删除行、均值/中位数/众数填充、前向/后向填充、按组填充、标记为未知 |
| `DUPLICATE_ROWS` | 完全重复行 / 业务键重复 | 报告 | 保留首条/末条、按规则合并、人工确认 |
| `OUTLIERS` | IQR / MAD / 业务阈值 | 报告 | 标记、缩尾（winsorize）、剔除（必须说明） |
| `TYPE_MISMATCH` | 列内类型混杂 | 报告 | 转字符串、转数值、拆分列 |
| `UNIT_INCONSISTENT` | 列名/值里单位混用 | 报告 | 统一单位、拆分单位列 |
| `TOTAL_ROWS_MIXED` | 合计/小计/平均行混在数据里 | 报告 | 排除合计行、单独成表 |
| `TIME_GAPS` | 时间轴缺失/重复/倒退 | 报告 | 补齐时间轴、聚合重复点 |
| `CONSTANT_COLUMN` | 整列同值 | 报告 | 删除列（需确认） |
| `HIGH_CARDINALITY` | 类别列唯一值过多 | 报告 | 聚合、Top-N、编码 |
| `FUZZY_DUPLICATE` | 文本相似但非完全一致 | 报告候选 | 合并/标准化（需人工确认） |
| `UNIT_MISSING` | 列名没有单位，值范围可疑 | 报告 | 询问用户 |
| `DATE_FORMAT_MIXED` | 同一列多种日期格式 | 报告 | 统一格式、拆分列 |

### 2.3 绝对不自动做

- 用 0 填充缺失值后当作真实值；
- 删除“看起来异常”的行；
- 把不同来源、不同口径的表按列名自动合并；
- 把 `万元` / `%` / `人` 等单位静默换算；
- 用 LLM 生成缺失行、缺失列或“合理”的合计；
- 覆盖原始文件或原始 `RawTable`。

## 3. 质量维度

| 维度 | 检查 | 示例 |
|---|---|---|
| 完整性 | 缺失值、空列、空表 | `销售额` 缺失 12% |
| 唯一性 | 完全重复行、业务键重复 | 同一城市+月份出现两条 |
| 有效性 | 类型、范围、格式 | 日期列里出现 `暂无` |
| 一致性 | 单位、口径、时间粒度 | 一半是 `万元`，一半是 `元` |
| 连续性 | 时间轴缺口、重复、倒退 | 1 月后直接 3 月 |
| 分布 | 异常值、长尾、常量列 | 销售额出现负值 |
| 结构 | 合计行混入、多层表头 | 最后一行是“合计” |
| 可解释性 | 每个问题有位置、数量、示例 | 不能只说“数据质量差” |

> 准确性（accuracy）无法在没有权威对照源时自动判断；只能报告“可疑值”，不能断言“错误值”。

## 4. 清洗报告格式

每次清洗（包括 dry-run）都生成 `cleaning_report.json`：

```json
{
  "dataset_id": "ds_ab12cd34ef56",
  "table_id": "sales_2024",
  "version": 1,
  "source": {
    "path": "uploads/2024_sales.xlsx",
    "sha256": "…",
    "sheet": "销售",
    "source_kind": "file"
  },
  "summary": {
    "rows_before": 1200,
    "rows_after": 1200,
    "columns_before": 8,
    "columns_after": 8,
    "auto_actions": 2,
    "pending_actions": 2,
    "blocking_issues": 0
  },
  "actions": [
    {
      "tool": "normalize_headers",
      "column": null,
      "strategy": "trim_whitespace",
      "affected": 3,
      "reason": "列名首尾空白"
    },
    {
      "tool": "coerce_numeric",
      "column": "销售额",
      "strategy": "numeric_text",
      "affected": 1200,
      "reason": "整列可解析为数值"
    }
  ],
  "issues": [
    {
      "code": "MISSING_VALUES",
      "severity": "warn",
      "column": "利润",
      "count": 144,
      "ratio": 0.12,
      "examples": ["第 18 行", "第 25 行"],
      "suggestion": "确认缺失原因；不要默认填 0"
    },
    {
      "code": "TOTAL_ROWS_MIXED",
      "severity": "warn",
      "column": "城市",
      "count": 1,
      "examples": ["合计"],
      "suggestion": "画图前排除合计行"
    }
  ],
  "assumptions": [
    "百分比列按原值保留，未转成小数",
    "金额单位沿用列名中的“万元”，未换算"
  ],
  "artifacts": {
    "cleaned_parquet": "runtime/datasets/ds_ab12cd34ef56/cleaned/sales_2024_v1.parquet",
    "raw_parquet": "runtime/datasets/ds_ab12cd34ef56/raw/raw_0.parquet"
  }
}
```

### 报告约束

- `issues[].code` 必须是稳定枚举，便于测试和前端渲染；
- `severity` 只能是 `info` / `warn` / `error`；
- `error` 表示无法继续生成图表（如 0 行、全部为空、无法识别表头、单位冲突无法解释）；
- 每个 action 必须能回答“改了什么列、改了多少行、为什么”；
- 报告与清洗后的 parquet 同目录，版本号递增，不覆盖上一版；
- 原始文件与原始 `RawTable` 只读保留，预览页可对比清洗前后。

## 5. 与 series / 图表的衔接

- 清洗后的表先进入 `build_profile_from_df`，再进入 `build_series_catalog`；
- series 的 `extra_semantics` 增加：
  - `source_kind`（file / database / api / document / archive）；
  - `source_table`；
  - `cleaning_version`；
  - `cleaning_report` 路径或 ID。
- 图表任务默认使用清洗后的版本；如果用户要求“用原始数据”，显式走 `raw` 版本；
- 如果存在 `error` 级问题，不进入图表规划，直接返回可读的错误与清洗报告；
- 如果只有 `warn`，图表可以生成，但报告/预览里要显示限制说明。

## 6. 规则实现建议

```text
service/data_ingestion/cleaning/
├── __init__.py
├── models.py      # CleaningIssue / CleaningAction / CleaningReport
├── rules.py       # 规则注册表：code、severity、默认动作、检测函数
├── profile.py     # 质量检查（只读）
├── plan.py        # 把 issues + 用户意图转成 actions（dry-run）
├── apply.py       # 执行 actions，返回新 DataFrame + 实际 affected
├── report.py      # 生成/读写 JSON
└── adapters.py    # 可选：Docling / OCRFlux 抽取适配
```

### 实现注意

- **不要**在 `rules.py` 里写死业务列名（如 `销售额`、`城市`）；用语义角色和通用模式；
- 规则阈值集中在常量/配置，不在多个函数里重复；
- 每个规则只负责检测或执行一件事，便于单测；
- `apply.py` 必须返回实际影响行数，不能只返回“成功”；
- 所有新列/新表都要带来源说明，禁止静默丢列；
- 日志用 `service.observability.get_logger`，不要 `print`；
- 错误信息带表名、列名、行号示例，方便用户定位。
