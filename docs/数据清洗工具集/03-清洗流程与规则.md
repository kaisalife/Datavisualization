# 面向可视化的清洗流程与规则

## 1. 总体流水线

```text
原始输入（文件 / DB / API / 图片 / PDF / Office）
        │
        ▼
┌─────────────────────┐
│ 1. 接入与抽表        │  MIME、编码、大小、哈希、来源；reader → RawTable
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│ 2. 安全结构归一化    │  列名、重复列、表头、标题行、空白 sheet（已有）
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│ 3. 值归一化          │  数值文本、空值占位符、类型（已有，保守整列回退）
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│ 4. 可视化画像        │  角色、时间性、基数、单位、缺失、重复、极值、标签
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│ 5. 候选 series       │  splitter 产出 1..n 条可视化切片（已有）
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│ 6. 图表契约评估      │  对每个（series × chart_type）给出 ready/needs/not_fit
└─────────────────────┘
        │
        ├── ready ───────────────► 9. 图表规划
        │
        └── needs/not_fit
                │
                ▼
┌─────────────────────┐
│ 7. 准备策略          │  2–4 个方案；组合操作；带取舍与影响预览
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│ 8. dry-run / commit  │  用户或 agent 确认；生成 prepared series 变体
└─────────────────────┘
        │
        └── 回到 6 重新评估（直到 ready 或明确不画）

图表生成后：
┌─────────────────────┐
│ 10. 渲染后数据检查   │  空 series / 全空 / 全 0 / 类型偏离（已有）
└─────────────────────┘
        │
        └── 反馈到 6/7：换策略、换图型或明确告知用户
```

### 与“通用清洗”的区别

| 通用清洗 | 本项目可视化准备 |
|---|---|
| 以“表是否干净”为目标 | 以“图是否能正确、可读地表达”为目标 |
| 全局规则，一次性执行 | 按图表意图和 series 选择策略 |
| 默认删/填/改 | 默认保留，修改需显式确认 |
| 输出一张清洗后的表 | 输出多个带来源和变更清单的 prepared series 变体 |
| 清洗完再画图 | 准备与图表契约、渲染检查形成闭环 |

## 2. 可视化画像（只读）

画像在 `RawTable` 归一化之后、series 拆分前后计算，不改变数据。它只回答“这份数据对图表意味着什么”。

### 2.1 基础信息

| 字段 | 说明 |
|---|---|
| `rows` / `columns` | 行数、列数 |
| `roles` | 每列语义：time / measure / dimension / id / unknown |
| `time_like` | 是否有可用时间轴 |
| `row_labels` | 行标签数（时间点或类别数） |
| `measure_count` | 指标数 |
| `numeric_columns` | 可数值化的列 |
| `value_min` / `value_max` | 数值范围 |
| `non_negative` | 是否全部非负 |
| `all_equal` | 是否所有值相同 |
| `cardinality` | 各维度唯一值数 |
| `label_length` | 最长标签长度 |
| `missing_ratio` | 各列缺失比例 |
| `duplicate_rows` | 完全重复行数 |
| `duplicate_keys` | 候选业务键重复数 |
| `time_order` | 时间是否单调、是否有重复/缺口 |
| `unit_hints` | 列名/值里的单位线索 |
| `scale_ratio` | 多指标之间最大/最小量级比 |
| `outlier_ratio` | 极端值占比（IQR/MAD，仅参考） |

### 2.2 可视化信号

信号是“对图表有影响的问题”，不是通用数据质量指标。每条信号必须带 `code`、`severity`、
`affected_charts`、`column`、`count/ratio`、`examples`、`suggested_ops`。

| 信号码 | 含义 | 影响的图 | 默认策略 |
|---|---|---|---|
| `VIS_NO_MEASURE` | 没有可数值化的指标 | 全部 | 阻断；先修表头/数值列 |
| `VIS_NO_AXIS` | 没有时间或类别轴 | Line/Bar/Pie 等 | 可改用 Scatter/Histogram，或补轴 |
| `VIS_NON_NUMERIC_MEASURE` | 指标列大部分不是数值 | 全部 | 报告；确认是否单位/文本混入 |
| `VIS_ALL_NULL` | 指标列全空 | 全部 | 阻断 |
| `VIS_MISSING_VALUES` | 关键列有缺失 | 全部 | 折线保留缺口；构成图排除并说明；填充需确认 |
| `VIS_CONSTANT` | 指标整列同值 | 趋势/关系/分布 | 警告；改用对比/表格 |
| `VIS_ALL_ZERO` | 全部数值为 0 | 全部 | 警告；检查筛选/聚合 |
| `VIS_NEGATIVE_FOR_PART` | 含负值 | Pie/Treemap/构成 | 饼图不可用；改 Bar/Line 或过滤 |
| `VIS_HIGH_CARDINALITY` | 类别数超过图表上限 | Bar/Pie/Line | Top-N + 其他、分组、横向条形 |
| `VIS_LONG_LABELS` | 标签过长 | Bar/Pie/Line | 截断/换行/旋转（视图层） |
| `VIS_TOO_FEW_POINTS` | 时间点/观测过少 | Line/Scatter/Histogram | 改 Bar/直接标注，或补数据 |
| `VIS_TOO_MANY_POINTS` | 点数过多 | Line/Scatter | 重采样/缩放/抽样显示 |
| `VIS_TIME_UNORDERED` | 时间乱序 | Line/Area/Candlestick | 排序 |
| `VIS_TIME_DUPLICATE` | 同一时间点多行 | Line/Area | 聚合（sum/mean 按语义） |
| `VIS_TIME_GAP` | 时间轴缺口 | Line/Area | 保留断点、重采样或补时间轴（需确认） |
| `VIS_MIXED_GRAIN` | 日/月/年混用 | 时间图 | 统一粒度或拆图 |
| `VIS_TOTAL_ROWS` | 合计/小计/平均行混入 | Bar/Pie/Line | 排除合计行 |
| `VIS_DUPLICATE_ROWS` | 完全重复行 | Bar/Pie | 聚合、保留首/末（需确认） |
| `VIS_DUPLICATE_KEYS` | 业务键重复（如城市+月份） | Bar/Pie/Line | 聚合、拆分多系列、保留首/末（需确认） |
| `VIS_UNIT_MIXED` | 单位混用 | 全部 | 拆单位列、换算（需确认）、分图 |
| `VIS_UNIT_UNKNOWN` | 指标无单位 | 全部 | 图上标注“单位未知”，不静默假定 |
| `VIS_SCALE_MISMATCH` | 多指标量级差过大 | Line/Bar | 双轴、分图、对数轴（视图） |
| `VIS_OUTLIER_DOMINATES` | 极值压扁其余数据 | Line/Bar/Scatter | 对数轴/缩放/单独标注（视图） |
| `VIS_SINGLE_CATEGORY` | 只有一个类别 | Pie/Bar | 饼图无意义；改指标卡/直接标注 |
| `VIS_DUPLICATE_LABELS` | x 轴标签重复 | Bar/Line | 聚合或加分组维度 |
| `VIS_HIERARCHY_MISSING` | 层级图缺层级 | Treemap/Sunburst | 改 Bar 或补层级 |

> `severity` 统一为 `info` / `warn` / `blocker`。`blocker` 只表示“当前图表类型无法正确表达”，
> 不表示数据本身错误；换图型或执行建议操作后可以解除。

## 3. 准备操作目录

操作分两类：**数据操作**改变值/行/列；**视图操作**只影响图表呈现，不改数据。

### 3.1 数据操作

| 操作 | 作用 | 典型场景 | 是否改变数据 | 默认策略 |
|---|---|---|---|---|
| `normalize_schema` | 列名去空白/重复列加后缀 | 手写 CSV、合并表头 | 列名 | 自动 |
| `coerce_numeric` | 数值文本转数值 | `1,200`、`12.5%` | 列类型/值 | 自动（整列失败则回退） |
| `exclude_rows` | 按明确条件排除行 | 合计行、页脚、空行 | 行 | 需确认/可自动仅限“合计”模式 |
| `filter_rows` | 按用户条件筛选 | 时间范围、地区 | 行 | 需确认 |
| `aggregate` | 按维度/时间聚合 | 重复时间点、长表 | 行/值 | 需确认（或按契约安全聚合） |
| `pivot_long_to_wide` | 长表转宽表 | 城市/月份/销售额 | 结构 | 可自动（不改总量） |
| `top_n` | 保留前 N + 其他 | 类别过多 | 行/结构 | 需确认（有数据丢失） |
| `other_bucket` | 合并为“其他” | 类别过多 | 行/结构 | 需确认 |
| `resample_time` | 时间粒度重采样 | 日→月、秒→分钟 | 行/值 | 需确认 |
| `dedupe` | 重复行聚合/保留 | 重复录入 | 行 | 需确认 |
| `handle_missing` | 缺口/删除/显式填充 | 缺失 | 行/值 | 默认只保留缺口；填充必须显式 |
| `convert_unit` | 单位换算 | 万元→元 | 值 | 必须显式确认 |
| `split_unit_column` | 拆出单位列 | 单位混用 | 结构 | 可自动（不改值） |
| `derive_measure` | 派生指标 | 增长率、占比 | 值 | 需确认公式 |
| `sort_rows` | 排序 | 时间/排名 | 顺序 | 自动（可视化排序） |
| `limit_series` | 限制指标列数 | 上千设备列 | 列 | 需确认（按业务重要性 Top-N） |

### 3.2 视图操作（不改数据）

| 操作 | 作用 | 典型场景 |
|---|---|---|
| `axis_scale` | 线性/对数轴 | 极值压扁、跨量级 |
| `zoom_window` | 只显示某段 | 长时序局部 |
| `truncate_labels` | 标签截断/换行 | 长类别名 |
| `label_rotation` | 标签旋转 | 类别多 |
| `downsample_display` | 显示层抽样 | 点数过多 |
| `highlight_series` | 高亮重点系列 | Top-N 中的重点 |
| `annotate_unit` | 图内标注单位 | 单位未知/保留原单位 |
| `dual_axis` | 双轴 | 两指标量级差大 |

> 视图操作必须写进计划，便于复现；但它们不能改变数据值，也不能用来掩盖数据问题。

## 4. 策略优先级

准备策略不是“越干净越好”，而是按影响从低到高选择：

1. **不改数据**：排序、视图缩放、标签处理、单位标注；
2. **不改总量**：长转宽、拆分单位列、列名归一化；
3. **改变结构但可解释**：聚合重复时间点、重采样（需说明口径）；
4. **有数据丢失**：Top-N、排除行、去重（必须确认并记录）；
5. **改变数值含义**：单位换算、缺失填充、派生指标（必须显式确认）。

### 4.1 策略矩阵（示例）

| 问题 | 方案 A（保守） | 方案 B（可读性） | 方案 C（业务口径） |
|---|---|---|---|
| 类别 40 个 | 全部画横向条形，滚动查看 | Top 10 + 其他 | 按上级维度分组的 Bar/Heatmap |
| 时间点重复 | 保留原始行，图会来回折 | 按时间 sum/mean 聚合 | 按业务键拆分多系列 |
| 时间缺口 | 保留断点 | 按粒度补时间轴（显式） | 只在有数据区间出图 |
| 缺失 20% | 折线保留缺口 | 删除缺失点（明确说明） | 按组均值/前向填充（需业务确认） |
| 含负值且用户要饼图 | 改 Bar/Line | 过滤负值后画饼（需说明） | 拆“正/负”两张图 |
| 两个指标量级差 1000 倍 | 分两张图 | 双轴 | 对数轴（视图） |
| 有合计行 | 排除合计 | 单独画“总计”指标卡 | 保留合计并标注 |

### 4.2 策略优先级（配置优先级）

从高到低：

1. 用户显式指令（“只画 2024 年”“不要动数据”“用万元”）；
2. skill 提供的领域策略（高频/K 线/多序列/多模态）；
3. 图表契约的默认策略；
4. 项目默认策略。

任何层都可以把操作设为 `never`，例如 `handle_missing.fill = never`。

## 5. 准备计划与变更清单

### 5.1 计划结构

```json
{
  "dataset_id": "ds_ab12cd34ef56",
  "series_id": "sales_2024.销售额",
  "intent": {
    "chart_type": "Pie",
    "analysis_task": "composition",
    "max_categories": 6,
    "missing_policy": "report"
  },
  "base_version": 0,
  "strategy": "readable",
  "operations": [
    {
      "op": "exclude_rows",
      "kind": "data",
      "params": {"mode": "total_rows"},
      "affected": 1,
      "reason": "排除合计行，避免份额重复计算",
      "requires_confirmation": false
    },
    {
      "op": "top_n",
      "kind": "data",
      "params": {"column": "城市", "n": 6, "other": true},
      "affected": 34,
      "reason": "饼图最多 6 个扇区，其余合并为其他",
      "requires_confirmation": true
    }
  ]
}
```

### 5.2 执行结果与变更清单

每次 `dry-run` 和 `commit` 都返回同一结构，`committed=false/true` 区分：

```json
{
  "dataset_id": "ds_ab12cd34ef56",
  "series_id": "sales_2024.销售额",
  "variant_id": "v1",
  "committed": true,
  "before": {"rows": 1200, "columns": 3, "fitness": "needs_preparation"},
  "after": {"rows": 6, "columns": 3, "fitness": "ready"},
  "operations": [
    {"op": "exclude_rows", "affected": 1, "reason": "合计行"},
    {"op": "top_n", "affected": 34, "reason": "Top 6 + 其他"}
  ],
  "signals_after": [
    {"code": "VIS_NEGATIVE_FOR_PART", "severity": "blocker", "count": 0}
  ],
  "artifacts": {
    "parquet": "runtime/datasets/ds_ab12cd34ef56/visual/sales_2024.销售额/v1.parquet",
    "manifest": "runtime/datasets/ds_ab12cd34ef56/visual/sales_2024.销售额/v1.json"
  },
  "requires_confirmation": false,
  "assumptions": ["金额单位沿用列名中的“万元”，未换算"]
}
```

### 5.3 约束

- 原始表、原始 series 只读；
- 每个操作必须回答“改了什么、多少行/列、为什么”；
- `dry-run` 不得写 parquet，只能写临时预览或内存对象；
- `commit` 生成新变体，版本号递增，不覆盖旧版本；
- 同一输入 + 同一策略 + 同一参数 → 同一输出；
- 任何有数据丢失/数值含义改变的操作，`requires_confirmation=true`；
- 准备失败不能导致图表任务直接崩溃，必须回退到原始版本并给出明确原因。

## 6. 与 series / 图表的衔接

### 6.1 series 元数据

在 `SemanticSeries.extra_semantics` 增加：

```json
{
  "visual": {
    "roles": {"月份": "time", "销售额": "measure", "城市": "dimension"},
    "signals": [
      {"code": "VIS_HIGH_CARDINALITY", "severity": "warn", "column": "城市", "count": 40}
    ],
    "default_fitness": {
      "Line": "ready",
      "Bar": "needs_preparation",
      "Pie": "not_fit"
    },
    "preparations": [
      {"variant_id": "v1", "strategy": "readable", "fitness": {"Bar": "ready"}}
    ]
  }
}
```

规划阶段只读这份摘要，不读 parquet；需要细节时再调用 `assess_visual_fitness` / `preview_preparation`。

### 6.2 plan 增加准备引用

```json
{
  "series_id": "sales_2024.销售额",
  "preparation_id": "v1",
  "chart_type": "Bar",
  "x_axis": "城市",
  "y_axis": ["销售额"]
}
```

- `preparation_id` 为空表示使用原始 series；
- 生成代码仍然只从 series 读取数据，准备变体对生成器表现为“另一个可读 series”；
- 不把文件路径或 DataFrame 塞进 plan / prompt。

### 6.3 渲染后反馈

`chart_data_check` 的问题映射：

| 图表检查 | 可能的准备问题 | 建议 |
|---|---|---|
| `CHART_DATA_EMPTY` | 指标全空、筛选过严、Top-N 后为空 | 回退原始版本、放宽筛选、换指标 |
| `CHART_DATA_ALL_NULL` | 数值列未转换、单位混入 | 重新评估 `VIS_NON_NUMERIC_MEASURE` |
| `CHART_DATA_ALL_ZERO` | 聚合口径错误、筛选错列 | 检查 `aggregate` / `filter_rows` |
| `CHART_DATA_MOSTLY_EMPTY` | 缺失严重、时间轴错位 | 建议保留缺口/聚合/换图型 |
| `CHART_TYPE_MISMATCH` | 计划与生成代码不一致 | 不改数据，修 plan 或生成代码 |

反馈只生成建议，不自动改数据；是否重试由图表 debug 循环决定。

## 7. 实现结构（建议）

```text
service/data_ingestion/visual/
├── __init__.py
├── models.py          # VisualIntent / VisualSignal / ChartContract / PreparationPlan
├── contracts.py       # 图表契约注册表（加载 configs/visualization_contracts.json）
├── profile.py         # 可视化画像与信号计算（只读）
├── fitness.py         # 按图表契约评估 ready/needs/not_fit
├── strategies.py      # 问题 -> 候选策略（含取舍）
├── operations.py      # 数据/视图操作实现（纯函数 + 影响统计）
├── plan.py            # 组合、校验、dry-run
├── variants.py        # prepared series 变体落盘/读取/TTL
├── feedback.py        # chart_data_check -> 信号映射
└── adapters.py        # 可选：Docling / OCRFlux 抽取适配
```

### 实现注意

- **不要在 `operations.py` 里写死业务列名**；列通过 `VisualIntent` / 策略参数传入；
- 阈值集中在 `configs/visualization_contracts.json`，不在多个函数里重复；
- 每个操作只做一件事，返回实际影响行数和结果 DataFrame；
- 所有操作必须幂等，或明确声明不可重复执行；
- 日志用 `service.observability.get_logger`，不要 `print`；
- 错误信息带 series_id、列名、行号示例，方便定位；
- 大表采样预览，但对实际执行的行数统计要准确。
