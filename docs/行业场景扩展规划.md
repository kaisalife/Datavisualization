# 行业场景扩展规划（图表实用性二期）

> 定位：把「数据可视化服务」从通用图表能力推向各行各业的**高频业务形态**。
> 原则不变：行业语义进 **skill**（bash frontmatter 场景指南）、API 表达进 **RAG**、
> 跨类型高级用法进 **Feature** 文档；数据层不认识行业，plan schema 保持 `series_id`
> 单一契约，不在 Python 里堆 `if 列名 == "开盘"` 的行业特判。

## 一、家底与缺口

| 层 | 现状 | 结论 |
|---|---|---|
| pyecharts 类型 | plan `ChartType` 18 种（Line/Bar/Scatter/Pie/Area/Histogram/Boxplot/Heatmap/Candlestick/Radar/Funnel/Gauge/Treemap/WordCloud/Graph/Parallel/Sankey/ThemeRiver） | 覆盖大多数业务形态；缺 Map/Geo/Sunburst/PictorialBar（schema 扩展题，P2） |
| RAG 知识库 | 176+ 篇官网例程（Map/Geo/Sunburst/PictorialBar 等未入 plan 的类型也有文档） | API 表达层**不是瓶颈** |
| Feature 高级用法 | markLine/markArea/断轴/labelLayout/富文本 tooltip/dataZoom 六篇 + 检索通道 | 行业形态的"表达材料"已备好 |
| 场景技能 | 4 个：high-frequency-timeseries / financial-candlestick / many-series-timeseries / multimodal-extracted-table | **行业业务形态层是唯一大缺口** |
| 守护层 | `chart_data_check` 对 Bar+Line 双轴（表内叠加辅助层）不判偏离；polish 会合并叠加子图坐标轴 | 组合图可以放心让 LLM 生成 |

**核心判断**：各行各业的可视化需求映射到数据形态只有有限几种
（时间趋势、类目对比、构成、分布、时段×类目矩阵、单指标状态、转化递减、
观测值分组比较）。行业化 = **形态识别（已基本具备）+ 行业术语命中 + 业务判断规则**。
后者是 skill 层的正事。

## 二、行业形态映射（需求 → 形态 → 载体）

| 行业 | 高频需求 | 图形态 | 现状缺口 |
|---|---|---|---|
| 制造/质量 | 不良项帕累托分析 | Bar 排行 + Line 累计占比 **双轴** + 80% 参考线 | 组合图没人主动做 |
| 制造/工艺 | 良率/参数稳定性 | Line + **markLine 上下限/均值** | Feature 文档已有，缺 SPC 语义指南 |
| 电商/零售 | GMV 趋势十促销期 | Line/Area + **markArea 促销注记** | 缺"促销期标签与 x 轴类目逐字匹配"等坑 |
| 电商/增长 | 注册→下单→支付转化 | Funnel 递减语义 | 推荐器不主动给 Funnel |
| 互联网/SaaS | DAU 趋势、留存 cohort | 多周群组 → **HeatMap 矩阵** | 缺二维时间 transform 范式 |
| 交通/物流/园区 | 时段×星期客流/流量 | **HeatMap（星期×小时）** | 同上 |
| 医疗 | 门诊时段热力、指标参考区间 | HeatMap + markArea 正常区间 | 运营形态同上 |
| 能源/电力 | 逐日负荷曲线、峰谷时段 | 多日按小时对齐叠加 Line + markArea 峰谷 | 缺"多日对齐"transform 范式 |
| 金融（K线外） | 收益分布、回撤、相关性 | Histogram / Area / HeatMap 分裂形态 | financial-candlestick 只管 K 线 |
| 人力 | 薪酬分布对比、离职漏斗 | 分组 Boxplot+散点、Funnel | Boxplot 叠散点 polish 已支持，缺语义 |
| 行政/公共 | 区域对比、财政构成 | Bar/Treemap/Pie | 无缺口（通用形态） |
| 客服/工单 | 工单关键词 | WordCloud（**需关键词计数列**，分词暂不支持） | 文本抽取是 P2 |

## 三、路线分级

### P0 —— 纯 skill + 文档 + 验证（不动 schema / 数据层 / 推荐器）

按依赖排序，5 个场景技能：

1. **`pareto-quality`**（制造/质量，推广到"投诉原因/停机原因/成本项排名"）
   - 形态：类目排行 Bar 双轴 + 累计占比 Line（`yAxisIndex=1`）+ 80% markLine
   - skill 要点：累计占比**在 pandas 完成**（`transform_hint` 范式：`cumsum/sum*100`）；
     双轴 y 轴 domain 0–100；`chart_data_check` 的 Bar+Line 已视为合法
   - 触发词：不良/缺陷/帕累托/主次因素/二八/投诉原因/停机原因/成本构成排名
2. **`spc-stability`**（制造/质量/运维监控）
   - 形态：Line + markLine（均值 + 上下控制限，数值在 pandas 算好传入）或 markArea 正常带
   - 触发词：良率/直通率/波动/控制限/超上限/报警/标准值/目标范围/稳定性
3. **`temporal-heatmap`**（交通/医疗/能源/互联网通用——产出密度高）
   - 形态：长表 time+维度+指标（或 日期+小时）透视成 星期×小时（日期×小时）宽表 → HeatMap + visualmap
   - skill 要点：二维时间透视 transform 范式（`dt.hour`/weekday 中文标签排序）、
     空 bucket 用 None 不补 0、cohort 留存的是同 skill 变体
   - 触发词：时段/星期/小时/班次/客流/挂号/流量/峰谷/热力/留存/cohort
4. **`funnel-conversion`**（电商/增长/HR 流程漏斗）
   - 形态：递减类目值序列 → Funnel（第一步基数放最上）
   - 要点：chart_recommend 不主动给 Funnel——skill 索引让 LLM 在"转化/环节"
     语义下自己选；递减校验（下一步 > 上一步给 warning 不硬纠）
   - 触发词：漏斗/转化/环节/uv/曝光→成交/报名/录取/离职流程
5. **`gauge-kpi-snapshot`**（管理驾驶舱/设备状态单指标）
   - 形态：单值（或少数几个）系列 → Gauge（达标率/完成率/负荷率/水位）
   - 要点：单行单列数据不产 Bar/Pie 的形态判定、Gauge 需要显式 min/max 域
   - 触发词：仪表/达标率/完成率/利用率/水位/负荷率/达成

### P1 —— 半代码扩展（skill 为主 + 推荐/守护小改 + 更多 Feature 文档）

6. `retail-promotion`（电商/零售促销季）：markArea 注记 + 促销标签与 x 轴类目
   **逐字匹配**规范（写进 skill；Feature/markarea 文档补一节）；
   触发词：促销/大促/节日/双十一/春节/活动期/同比清洗
7. `hr-compensation`（人力）：分组 Boxplot+散点正规化（现有 polish 联动轴合并已就绪），
   transform 范式按分组列取观测值数组（不做直方图分箱）
8. `energy-load-profile`（能源/电力）：多日按小时对齐（小时内平移折线/多列宽表）
   transform 范式 + 峰谷 markArea；与 temporal-heatmap 互补引用
9. `finance-portfolio`（金融双形态）：收益率分布 Histogram + 回撤 Area +
   相关性矩阵 HeatMap；多形态单一 skill 里引用 Feature/Histogram 指南
10. 推荐器小改（确定性，不属行业硬编码）：单值单指标（rows=1 measure=1 非 time_like）
    时不给 Bar/Pie 强推，给出 Gauge 备选（适配 gauge skill 的形态前置条件）

### P2 —— schema/系统扩展（重投入，允许延后）

11. **地理可视化**（区域销售/门店分布）：`ChartType` 增加 `Map/Geo` + 地名清洗
    （"北京市"→ map json 键）+ 地名列检测提示；RAG 已有 Map/Geo 全例程；
    需写一层「地名 → register_map」的固定数据准备（技能正文给模板）
12. **Sunburst 层级构成**（组织/产品线/预算树）：需要父子层级推断
    （列 B 取值 ⊆ 列 A）或手工层级，treemap 单层先行够用
13. **WordCloud 文本分词**（客服工单/评论）：需要 jieba 依赖与停用词表；
    先支持"关键词计数"形态（表已含 keyword/count 两列），分词另立决策
14. 所有大屏/3D/gl/实时流图：**不做**（超范围）

## 四、机制与验收（每个新技能统一走这套）

### 4.1 实际场景用例设计规范（先于实现确定）

用例按「真实业务场景」组织，三要素都要业务保真，禁止"给图造玩具两列表"：

1. **数据 = 业务系统原始导出**
   - 行粒度 = 业务事件（每笔不良记录 / 每次挂号 / 每条会话），**聚合由管线自己做**
   - 列名用行业原生词（`发生日期`/`不良描述`/`判定数量`/`产线`），不用 `category/value`
   - 分布带行业真实特征：长尾（帕累托本来就是 2/8）、停机/闭诊缺失段、
     冗余列（单号/备注/操作员，含 `—` 占位）、同类目多种写法（`划伤`/`表面划伤`，考验不臆造合并）
   - 文件格式贴近真实来源：CSV（GBK 兼容）/ xlsx 合并表头 / 长表，混合使用
2. **话术 = 用户真实问法**："帮我分析这两周不良集中在哪些项目，做个主次因素排列"，
   而不是"画个柱状图"；话术里只给业务目标，不给图型答案（考验规划器自主选型）
3. **验收 = 业务结果正确优先，视觉要素其次**：
   - 聚合口径：帕累托按不良项 sum、漏斗每会话只算最深环节、热力图空 bucket 保留 None
   - 排序/区间：Bar 降序、累计占比收口 100%、控制限在数据范围外留白
   - 图型：plan.chart_type、组合结构（双轴）、参考线/注记存在
   - 防呆负断言：不把 0 补成数据点、不把维度列遭劫持成 x 轴、占比不手算错

用例文件：`tests/fixtures/industry/<场景名>/*`（数据 + 用例说明 YAML/README）。
单测跑 shape/技能触发与口径纯函数（无 LLM）；真模型 e2e 每场景 1 条（needs_llm 手工档，
改技能/生成器时重跑），断言落在业务验收而非 HTML token 堆砌。

### 4.2 交付物清单（每个技能）

1. **SKILL.md**：frontmatter `name/description/chart_types/analysis_tasks/time_like/
   min_rows/min_series/user_keywords` + 正文四件事：什么时候用（业务判断）、
   数据加工范式（业务粒度 → 图表粒度的完整示例）、生成代码要点（option 约定）、踩坑点
2. **规划索引零负担**：主 prompt 只注入索引（现机制），普通数据不加载
3. **单测**（核心白名单）：形态+关键词命中/普通数据不命中（test_skill_registry.py）；
   fixture 过 ingest 的 shape 断言（触发链路）
4. **真机 e2e**：`tests/test_file/test_industry_e2e.py` 每场景 1 条（§4.1 规范）
5. **prompt/守护同步**：涉及 prompt 规则时同步 test_chart_prompt_rules；
   涉及 plan/图表字段时同步 test_plan_contract
6. **RAG/Feature 联动**：新 API 用法先 Feature/RAG 文档，skill 正文引用不复制

## 五、不做清单

- 不在 chart_recommend / diversify / polish 里写行业 if
- 不为行业新增 ChartType（P2 之外不碰 schema）
- 不做分词/情感分析/预测模型（那是分析服务不是可视化）
- 不把行业模板固化成固定 prompt 段落（技能正文按需加载即可）
